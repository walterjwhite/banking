Config, not code

Every entry — a mess charge, a chore reward — is a record in charges.json in the ledger, with a kind of debit or credit. The select swaps the declared fields live: a choice for where, a text box for what was left out, nothing at all for a simple bonus.

One form, both directions

A debit takes money out, a credit puts it in. Only the label, amount and questions differ; the form, the photo handling, the queue row and the parent PIN are identical, so the audit trail is uniform.

Camera, straight from the input

The input is type="file" accept="image/*" capture="environment". On Android Chrome that opens the rear camera immediately; on iPhone Safari it offers Take Photo or Photo Library; on a desktop it is the usual file picker. No getUserMedia, so there is no permission prompt and no camera stream left running — and the same input still works when the browser ignores capture. The tradeoff: capture is a hint to skip the picker, so Android goes straight to the camera and cannot pick an older photo. Drop the attribute where the photo is optional (the reward above), keep it where the picture is the evidence.

Picture handling

The photo is capped at 1920×1080, re-encoded as JPEG and stripped of location metadata, then written to the private ledger as evidence/2026-11/<id>.jpg. The issue keeps the path and a SHA-256, so a parent can check the photo later without it ever being served from this public shell.
